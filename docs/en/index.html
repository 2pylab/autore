autore

auto + re(resume / retry / restart)

Hit a usage limit on Claude Code? This lightweight watcher waits for the reset and automatically resumes your work.
(Also works with other AI CLIs like OpenCode)

v2.4.0 Multi-CLI (Claude Code · OpenCode) Linux · macOS bash 3.2+ Telegram alerts MIT License
Install now GitHub repo

01Features

No more babysitting the rate limit — when it resets, your session picks up where it left off.

🔁 Auto-resume

Detect limit → parse reset time → sleep → type the resume message into your session. Conversation context stays intact.

🤖 Multi-CLI

--cli can watch other AI CLIs — though OpenCode already retries rate limits on its own, so this is mainly useful for Telegram alerts.

⏱ Layered time parser

Handles 3pm, 3:30 PM, 15:00, Jul 28 at 3pm (weekly limits), tomorrow at 9am, midnight/year rollover, and wrapped lines.

🛡 Safety guards

Dedupes identical limit messages, rejects implausible times (limit-window validation), periodic retry on parse failure.

📨 Telegram + generic hook

Bot notifications on watcher start, limit detection, resume, and retry, plus --notify-cmd for Slack, Discord, ntfy or desktop alerts.

✅ Resume verification

Skips sending if you already resumed by hand, warns when the screen does not react, and watches every pane in the session.

🔐 Signed updates

Replaces the script only when it matches the published SHA256 — auto-update aborts on any verification failure.

⏸ Interruption point

Saves a snapshot of the screen at the moment the limit hit. status shows when it stopped and resumed, last shows what it was doing.

🎨 Readable status output

status separates live state from recent logs with color-coded sections.

🌐 Bilingual output

CLI messages, logs, and Telegram alerts follow the OS locale (Korean/English).

🔄 Auto-update

Checks for a new version at watcher start and every 24h, verifies, and replaces itself. Disable with --no-auto-update.

🧪 Built-in self-test

--selftest runs 29 parser + state unit tests.

📦 One-line install

Installer with dependency checks and self-test. Linux and macOS supported.

02Install

Dependencies: tmux, GNU date (macOS: brew install coreutils), optional curl (for Telegram)

One-liner

curl -fsSL https://raw.githubusercontent.com/2pylab/autore/main/install.sh | bash

Or clone and install

git clone https://github.com/2pylab/autore.git
cd autore
./install.sh
CommandDescription
./install.shInstall to ~/.local/bin (default)
./install.sh --systemSystem-wide install to /usr/local/bin
./install.sh --prefix=PATHInstall to a custom path
./install.sh --uninstallUninstall

Updating

autore update          # check latest → verify → replace (auto backup)
autore update --check  # check only
Note for v1.x (claude-auto-resume) users: the project was renamed to autore in v2.0.0. Re-run the install one-liner above once — it installs autore and removes the old binary automatically. (The old claude-auto-resume update also fetches v2.0.0, but keeps the old command name — reinstalling is recommended. Existing log/PID files are picked up automatically.)

The downloaded file is only installed after passing a syntax check and the self-test, and the previous file is backed up to .bak. If the watcher is running it is stopped first — run start again afterwards.

03Usage

Two commands — start the watcher, then use your AI CLI as usual.

autore start     # ① start background watcher
autore attach    # ② attach to the AI CLI session → work as usual

Watching another AI CLI (e.g. OpenCode)

autore start --session opencode --cli opencode

Note: OpenCode has built-in rate-limit retry and resumes on its own — autore is only useful here if you want Telegram alerts, or for other AI CLIs without built-in retry.

2Start a chat with your bot, then get your chat ID via @userinfobot
3Add the two lines below to ~/.bashrc
4Run autore test-telegram — setup is complete when the test message arrives
export TELEGRAM_BOT_TOKEN="123456:ABC..."
export TELEGRAM_CHAT_ID="123456789"
⚠️ Passing the token via --telegram-token can expose it in ps output — environment variables are recommended.

05How it works

1Checks the AI CLI screen in tmux every 30s (last 40 lines; wrapped messages joined with the next 2 lines)
↓
2Detects the limit message → parses the reset time (implausible times outside the limit window are rejected; common provider phrasings — rate limit / too many requests / quota exceeded — are also detected)
↓
3Sleeps until reset time + buffer (90s)
↓
4Types the resume message into the session → Telegram alert
↓
5If still limited, retries at most twice (avoids spamming the session)

Every detected limit message is collected in ~/.autore-samples.log, so the parser can be updated safely if message formats change (--selftest: 16 regression tests).
