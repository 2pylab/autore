autore

auto + re(resume / retry / restart)

Claude Code의 사용량 제한에 걸리면, 리셋 시각까지 대기했다가 자동으로 작업을 이어가는 경량 감시 도구
(OpenCode 등 다른 AI CLI에도 사용 가능)

v2.5.0 멀티 CLI (Claude Code · OpenCode) Linux · macOS bash 3.2+ 텔레그램 알림 MIT License
지금 설치하기 GitHub 저장소

01기능

제한이 걸려도 잠이나 출근을 미룰 필요 없이, 리셋되면 알아서 작업이 다시 시작됩니다.

🖥 세션 한눈에

status가 tmux 세션 개수와, AI CLI가 어느 세션·pane·디렉터리에서 돌고 있는지 함께 표시. 프로세스 트리를 따라가 node로 보이는 실행도 찾아냅니다.

🔁 자동 재개

제한 감지 → 리셋 시각 파싱 → 대기 → 세션에 재개 메시지 자동 입력. 대화 맥락 그대로 복귀.

🤖 멀티 CLI

--cli 옵션으로 다른 AI CLI도 감시 가능. 단 OpenCode는 자체 재시도가 내장되어 있어, 텔레그램 알림이 필요한 경우 정도에만 유용.

⏱ 다단계 시각 파서

3pm, 3:30 PM, 15:00, Jul 28 at 3pm(주간 제한), tomorrow at 9am, 자정/연도 넘김, 화면 줄바꿈 처리.

🛡 안전장치

같은 제한 메시지 중복 처리 방지, 모순된 시각 거부(제한 창 검증), 파싱 실패 시 주기적 재시도.

📨 텔레그램 + 범용 훅

감시 시작 / 제한 감지 / 재개 완료 / 재시도 시 봇 알림. --notify-cmd로 Slack·Discord·ntfy·데스크톱 알림까지 연결.

✅ 재개 확인

대기 중 직접 이어갔으면 전송을 건너뛰고, 전송 후 화면 반응이 없으면 경고. 세션의 모든 pane을 감시.

🔐 서명된 업데이트

배포 SHA256과 대조해 일치할 때만 교체. 자동 업데이트는 검증 실패 시 무조건 중단(fail-closed).

⏸ 중단 시점 표시

제한에 걸린 순간의 화면을 스냅샷으로 저장. status로 "언제 멈췄고 언제 이어졌는지", last로 "무엇을 하다 멈췄는지" 확인.

🎨 보기 좋은 상태 출력

status가 현재 상태(실시간)와 최근 로그(과거 기록)를 컬러로 구분해 표시.

🌐 한/영 출력

OS 로케일에 따라 CLI 메시지·로그·텔레그램 알림·설치 스크립트가 한국어/영어로 자동 전환.

🔄 자동 업데이트

감시 시작 시 + 24시간마다 새 버전을 확인해 검증 후 자동 교체. --no-auto-update로 비활성화.

🧪 자가진단 내장

--selftest로 파서·상태기록 단위 테스트 29종 실행.

📦 원라인 설치

의존성 검사 + 자가진단 포함 설치 스크립트. Linux와 macOS 모두 지원.

02설치

의존성: tmux, GNU date(macOS는 brew install coreutils), 선택적으로 curl(텔레그램용)

원라인 설치

curl -fsSL https://raw.githubusercontent.com/2pylab/autore/main/install.sh | bash

또는 클론 후 설치

git clone https://github.com/2pylab/autore.git
cd autore
./install.sh
명령설명
./install.sh~/.local/bin에 설치 (기본)
./install.sh --system/usr/local/bin에 시스템 전체 설치
./install.sh --prefix=경로지정 경로에 설치
./install.sh --uninstall제거

업데이트

autore update          # 최신 버전 확인 → 검증 후 교체 (자동 백업)
autore update --check  # 새 버전 확인만
v1.x(claude-auto-resume) 사용자 참고: v2.0.0부터 이름이 autore로 바뀌었습니다. 위의 설치 원라인을 한 번만 다시 실행하면 autore로 설치되고 구버전 바이너리는 자동 정리됩니다. (기존 claude-auto-resume update로도 v2.0.0을 받을 수 있지만 명령어 이름이 그대로이므로 재설치를 권장합니다. 기존 로그·PID 파일은 그대로 이어서 사용합니다.)

다운로드한 파일은 문법 검사 + 자가진단 통과 후에만 교체하며, 기존 파일은 .bak으로 백업합니다. 감시 실행 중이면 자동 중지 후 교체하니 업데이트 뒤 start로 다시 시작하세요.

03사용법

두 명령이면 끝 — 감시를 켜고, 평소처럼 AI CLI를 쓰세요.

autore start     # ① 백그라운드 감시 시작
autore attach    # ② AI CLI 세션 접속 → 평소처럼 작업

OpenCode 등 다른 AI CLI 감시

autore start --session opencode --cli opencode

※ 참고: OpenCode는 레이트 리밋 자동 재시도가 내장되어 있어 autore 없이도 리밋 후 알아서 이어집니다. 텔레그램 알림을 받고 싶거나, 재시도가 없는 다른 AI CLI를 쓸 때 활용하세요.

명령설명
start [옵션]백그라운드 감시 시작 (tmux 세션 없으면 자동 생성)
stop감시 중지
status감시 상태(실시간) + 중단 시점 + 세션 + 텔레그램 설정 + 최근 로그 (컬러 출력)
last마지막 중단 시점 화면 스냅샷 + 중단 이력
logs [-f]로그 보기 (-f: 실시간)
attachAI CLI tmux 세션 접속
run [옵션]포그라운드 감시 (디버깅용)
update [--check]최신 버전으로 자동 업데이트 (--check: 확인만)
test-telegram텔레그램 연동 테스트 메시지 발송
checksum배포용 SHA256 출력 (릴리스 시 autore.sh.sha256 갱신용)
--selftest파서·상태기록 단위 테스트 29종
version버전 출력 (--version과 동일)
help도움말 (-h, --help와 동일)

주요 옵션 (또는 동명 환경변수)

옵션기본값설명
--session NAMEclaude감시할 tmux 세션명
--cli CMDclaude세션 생성 시 실행할 AI CLI (예: opencode)
--poll SEC30화면 확인 주기
--buffer SEC90리셋 후 여유 대기
--fallback SEC900시각 파싱 실패 시 재시도 대기
--max-resends N2같은 제한 메시지 최대 재전송
--message TEXT계속 이어서 진행해줘리셋 후 자동 입력 메시지
--no-auto-update활성자동 업데이트 비활성화
--auto-update-sec S86400자동 업데이트 확인 주기 (초)
--dry-run—실제 전송 없이 로그만 (테스트용)

전체 옵션은 autore help 또는 README 참조.

04텔레그램 알림 (선택)

감시 시작, 제한 감지, 재개 완료, 재시도 때마다 텔레그램으로 알림을 받습니다.

1텔레그램 @BotFather → /newbot → 봇 토큰 발급
2봇과 대화 시작 후 @userinfobot 등으로 채팅 ID 확인
3~/.bashrc에 아래 두 줄 추가
4autore test-telegram — 테스트 메시지가 오면 설정 완료
export TELEGRAM_BOT_TOKEN="123456:ABC..."
export TELEGRAM_CHAT_ID="123456789"
⚠️ 토큰을 --telegram-token 인자로 넘기면 ps 출력에 노출될 수 있으니 환경변수를 권장합니다.

05동작 원리

1tmux 세션의 AI CLI 화면을 30초마다 확인 (하단 40줄, 줄바꿈 메시지는 2줄 더 묶어서 파싱)
↓
2제한 메시지 감지 → 리셋 시각 파싱 (제한 창 밖의 모순된 시각은 거부, 프로바이더 공통 표현 — rate limit / too many requests / quota exceeded — 도 감지)
↓
3리셋 시각 + 버퍼(90초)까지 대기
↓
4세션에 재개 메시지 자동 입력 → 텔레그램 알림
↓
5여전히 제한 상태면 최대 2회까지만 재시도 (메시지 도배 방지)

감지된 실제 제한 메시지 원문은 ~/.autore-samples.log에 자동 수집되어, 메시지 형식이 바뀌어도 파서를 안전하게 업데이트할 수 있습니다 (--selftest 회귀 테스트 29종).

06법률 검토 및 면책조항

  • 이 도구는 AI CLI가 화면에 이미 표시한 제한 안내를 읽고, 안내한 리셋 시각까지 단순 대기한 뒤 사용자 본인의 세션을 재개하는 단순 대기·재개 스크립트입니다.
  • 사용량 제한을 우회하거나 회피하지 않으며, 각 서비스에 추가 API 요청을 전송하지 않고, 인증·접근 제어를 변경하지 않습니다. 제한이 해제된 후에만 정상적으로 재개합니다.
